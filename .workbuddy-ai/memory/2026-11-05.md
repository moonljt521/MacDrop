## 排查：Android 接收图片/视频后相册出现两份（未改代码）

根因：`MediaStoreStore.save()` 把收到的文件插入 `MediaStore.Downloads`（Download/来自另一台Mac），
MIME 按扩展名给成 image/*、video/*；`IS_PENDING=0` 后系统按 media_type 索引，图库查
`MediaStore.Images.Media` 时就能看到这条（集合不是互斥目录）。随后 `ReceiverService.onFinished`
在自动保存开关（默认 true）下再调 `saveToGallery()` 往 Pictures/MoonDrop、Movies/MoonDrop
复制一份 → 物理两条记录，相册两份。

同类隐患：
- `saveToGallery` 无幂等，同名再插会被系统改名 `xxx (1).jpg`；自动保存已开时列表里的
  「相册」按钮仍可点（MainActivity.kt:1184 / 1324），点一次多一份。
- 开关关掉只能阻止副本，原件仍进图库 → 开关语义与 UI 文案不符。
- iOS：`PhotoSaver.save()` 每次新建 PHAsset，自动保存 + ContentView 的「存入相册」按钮
  手动点一次会变两份；但接收流程本身幂等（TransferServer.finish 用 staging.removeValue），
  不会自动出现两份。
- macOS：无写 Photos 路径，接收只 moveItem 到 ~/Downloads/来自另一台Mac，无此问题。

建议方向（待用户确认后实施）：Android 按 MIME 分流，媒体直接写 Pictures/MoonDrop 或
Movies/MoonDrop 一次，不再复制；listReceived/clearReceived 同步覆盖新路径；手动按钮去重。
README 里「另存一份到相册」的文案也要跟着改。

## 已实施（大佬儿确认「按你的做」后）

- Android：`MediaStoreStore.save()` 按 MIME + 开关直接写最终目录（image→Images.Media/
  Pictures/MoonDrop，video→Video.Media/Movies/MoonDrop，其余→Downloads）；`listReceived()` /
  `clearReceived()` 改为遍历三个集合、按 RELATIVE_PATH 前缀过滤；`saveToGallery()` 改幂等 +
  移动语义（已在相册目录直接返回原 uri；否则复制成功后删掉原件，失败回滚副本）。
- Android：`ReceiverService.onFinished` 去掉自动复制线程，只按 relativePath 反馈文案；
  MainActivity 开关/说明/清空确认文案同步，已在相册目录的条目隐藏「相册」按钮，
  手动移动成功后 refreshReceived 刷新 URI。
- iOS：AppModel 新增持久化的 `savedPhotoPaths`（`com.macdrop.mobile.savedPhotoPaths`），
  自动保存与手动保存共用去重；ContentView 隐藏已保存项的按钮；deleteItems/clearReceived
  同步清理记录。
- 两份 README 的功能说明、数据位置、开发备注均已更新。
- 验证：`./gradlew assembleDebug --offline` BUILD SUCCESSFUL；
  `xcodebuild -scheme MoonDropMobile -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build`
  BUILD SUCCEEDED（scheme 名是 MoonDropMobile，不是 MoonDrop）。未 commit / push。
- 注意：升级前旧版本已产生的「原件 + 副本」不会自动合并，仍会看到两份，需手动删或
  用「清空已接收」把三处一起清掉。媒体只有一份后，清空已接收会连相册里那张一起删。

## 追加修正：清空已接收不再删相册照片（08:00）

大佬儿发现上一版清空会连相册里的照片一起删，确认是 Android 的副作用（原来「相册副本保留」的
语义被合成一份后丢掉了）。已按「照片进相册就是用户资产，与 iOS 对齐」修正：

- `GallerySettings` 新增 `galleryClearedAt()` / `markGalleryCleared()`（SharedPreferences 存秒级
  时间戳，写入时回退 1 秒，避免同一秒新收的文件被 `DATE_ADDED > ?` 永久隐藏）。
- `MediaStoreStore.clearReceived()` 只删 `Downloads` 集合条目 + 记时间戳；相册目录文件不删。
- `listReceived()` 对 Images/Video 集合的查询加 `DATE_ADDED > clearedAt`，文件保留但列表干净，
  之后新收的媒体正常出现。
- MainActivity 清空标题/确认框、两份 README 的功能说明与开发备注均已同步。
- 有意保留的差异：单条左滑删除 `delete(entry)` 仍会删掉相册里那张（用户明确针对单个文件），
  和批量清空区分开。iOS 本来就保留相册资产，无需改代码，已装的 Release 版不用重装。
- `./gradlew assembleDebug assembleRelease --offline` → BUILD SUCCESSFUL；
  新 release APK 08:03 生成，v2 签名校验通过。未 commit / push。
